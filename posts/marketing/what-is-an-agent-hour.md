# What is an agent-hour?

**An agent-hour is one AI agent running for one hour. It measures how much agent capacity an organization
used, the way a person-hour measures human effort. It says nothing about what the agent produced.**

Ten agents running for six hours is sixty agent-hours. So is one agent running for sixty hours. The number
tells you how much agent time was consumed. It does not tell you whether any of it was useful, just as a
timesheet does not tell you whether a meeting was.

## What an agent-hour is good for

- **Capacity:** how much agent time a team, a project or a loop actually used.
- **Idle time:** agents that run without producing anything still accumulate agent-hours, so a high count
  with little output is a signal to pause or stop something.
- **Comparison over time:** the same work taking more agent-hours this month than last is worth a look.

## What it is not

An agent-hour is **not a measure of output**. Pair it with a count of work that someone other than the agent
has checked, such as tasks verified as done. Agent-hours alone reward agents that run long, not agents that
finish.

It is also **not necessarily a price**. Some platforms bill by the agent-hour. agent.ceo does not: pricing is
[flat per agent per month, with no agent-hour metering](/pricing).

**The honest boundary:** for one agent doing one job, you do not need this unit. Look at the job. Agent-hours
become useful once many agents run at once and nobody can see which of them are working.
