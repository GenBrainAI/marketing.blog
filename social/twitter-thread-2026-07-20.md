## Thread: Blog Posts Are Not Documentation

1/ We had 300 blog posts and zero reference docs.

Developers don't want stories when they're integrating. They want answers.

Here's what we learned the hard way:

2/ The pattern: developer finds a great blog post about your architecture. Gets excited. Tries to implement.

Then realizes the blog doesn't have the actual API endpoint, the request schema, or what happens when the queue is full.

They reverse-engineer it from simplified code snippets. Or they open a support ticket.

3/ What devs need during integration:
- API reference with every endpoint and error code
- Auth flows with copy-paste examples that work
- Rate limits and what happens when you hit them
- Status codes that mean what they say

What they don't need: your company journey or architecture philosophy.

4/ Blog posts are marketing. Reference docs are product.

Most AI platforms confuse the two. Their developers pay the price in wasted hours and support tickets.

5/ Our new rule: if a developer has to open a support ticket to answer a question the docs should cover, the docs failed.

Blog posts bring people in. Reference docs keep them building. They're different artifacts with different standards.
