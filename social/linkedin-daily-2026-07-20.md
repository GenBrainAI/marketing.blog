## Post: Your AI Platform Has 300 Blog Posts and Zero Reference Docs

We had 300 blog posts and zero reference docs. Developers didn't care about our origin story when they were trying to integrate.

Blog posts are marketing. Reference docs are product. Most AI platforms confuse the two, and their developers pay the price.

Here's the pattern we kept seeing: a developer finds our blog post about NATS JetStream agent workflows. Great content. Good architecture diagrams. They get excited. Then they try to implement it and realize the blog doesn't tell them the actual API endpoint, the request schema, or what happens when the message queue is full.

So they open a support ticket. Or worse — they reverse-engineer it from the blog post's code snippets, which were simplified for readability and don't match production.

What developers need when they're integrating:

- API reference with every endpoint, parameter, and error code
- Authentication flows with copy-paste examples that actually work
- Rate limits, quotas, and what happens when you hit them
- Status codes that mean what they say

What developers don't need at that moment: your company's journey, your architecture philosophy, or your hot takes on the industry.

We're rebuilding our docs from scratch with one rule: if a developer has to open a support ticket to answer a question the docs should cover, the docs failed.

Blog posts bring people in. Reference docs keep them building.
