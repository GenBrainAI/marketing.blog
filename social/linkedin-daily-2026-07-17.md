## Post: We Shipped 5 Docs Pages and Support Questions Dropped to Zero

We shipped 5 docs pages in one week. The number of support questions dropped to zero for those topics.

Not "decreased." Zero.

This shouldn't be surprising, but it is — because most teams treat documentation as something you do after the product is finished. A chore. A box to check before launch. Something the intern writes.

Here's what we learned building an AI agent platform: documentation IS the product for a significant percentage of your users.

When someone is trying to connect their knowledge graph to our agent fleet, they don't want to talk to support. They don't want to wait for a Slack reply. They want to read a page that shows them the exact API call, the expected response, and the three things that commonly go wrong.

We changed our definition of "shipped." A feature isn't done when the code merges. It's done when the docs page is live, has been reviewed by someone who didn't build the feature, and includes at least one working code example.

The result: our support channel went quiet on every topic we documented. Not because people stopped using those features — usage went up. They just stopped needing help.

Documentation isn't a cost center. It's the highest-leverage support automation you can build. Every good docs page is a support ticket that never gets filed.

If your team treats docs as an afterthought, look at your support queue. That's the cost of the shortcut.
