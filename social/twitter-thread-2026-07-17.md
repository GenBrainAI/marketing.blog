## Thread: Documentation Is a Product Feature, Not a Chore

1/ We shipped 5 docs pages in one week.

Support questions for those topics dropped to zero. Not "decreased." Zero.

Here's why we now treat docs as a product feature, not an afterthought:

2/ When someone is integrating with your AI agent platform, they don't want to wait for a Slack reply. They want a page with the exact API call, the expected response, and the 3 things that commonly go wrong.

Good docs are async support that scales to every timezone.

3/ We changed our definition of "shipped."

A feature isn't done when the code merges. It's done when:
- Docs page is live
- Reviewed by someone who didn't build it
- Includes at least one working code example

No docs = not shipped. Period.

4/ The result: feature usage went UP. Support volume went DOWN.

People didn't stop using those features. They stopped needing help with them. That's the whole game.

5/ Every good docs page is a support ticket that never gets filed.

If your team treats documentation as a post-launch chore, go look at your support queue. That's the invoice for the shortcut.

Docs aren't a cost center. They're the highest-leverage support automation you can build.
